# AI Usage

## Что делалось с AI

- Первичная декомпозиция требований из `doc.md` в страницы, FSD-слои и сценарии проверки.
- Черновая структура компонентов списка, детальной страницы, формы ставки и секций карточки.
- Подбор коротких названий модулей и проверка соблюдения суффикса `*.component.tsx`.
- Подготовка тест-кейсов для search params, схемы ставки и MSW-store.
- Ревизия README и этого файла перед сдачей.

## Что решал кандидат

- Оставить проект в формате SPA на Vite без отдельного backend.
- Использовать OpenAPI-схему как источник TypeScript-типов через `openapi-typescript`.
- Разложить код по Feature-Sliced Design: `app`, `pages`, `widgets`, `features`, `entities`, `shared`.
- Держать API-слой тонким: `openapi-fetch`, query keys и функции endpoint-ов без дополнительного SDK.
- Использовать Zustand только для UI-state панели фильтров, а серверное состояние оставить в TanStack Query.
- Хранить фильтры в URL search params, чтобы состояние списка можно было открыть по ссылке.
- Сделать MSW-store stateful, чтобы ставка реально меняла список, детальную карточку и историю ставок.

## Какие AI-предложения были отклонены

- Генерация большого клиентского SDK поверх OpenAPI: для тестового SPA достаточно typed `openapi-fetch`.
- Добавление отдельного mock backend на Express/Fastify: MSW покрывает требование без второго процесса.
- Глобальный state manager для аукционов: серверное состояние уже ведет TanStack Query.
- Сложная карта маршрута и отдельные ViewModel-слои для каждой секции: это увеличило бы объем без пользы для проверки задания.
- E2E-тесты как обязательная часть сдачи: для текущего объема оставлены unit-тесты чистой логики.

## Что проверялось особенно внимательно

- Соответствие endpoint-ов OpenAPI: `POST /auctions/list`, `GET /auctions/{auctionUuid}`, `GET /auctions/{auctionUuid}/bets`, `POST /auctions/{auctionUuid}/bets`.
- Enum-значения типов, статусов и торгового состояния.
- Nullable-поля: скрытая цена, скрытые контакты, скрытая история ставок, отсутствие своей ставки.
- Валидация ставки на клиенте и в MSW-store: обязательность, положительная цена, `min`, `max`, `step`.
- Инвалидация query после mutation: список, детали и ставки.
- URL search params: безопасные fallback-значения при мусорных параметрах.
- Адаптивность списка, карточек и формы.

## Какие риски остались

- Runtime-валидация ответов API не добавлена, поэтому при реальном backend расхождение контракта поймается не на границе клиента.
- MSW покрывает основные edge cases, но не является полным симулятором production API.
- Production-сборка отключает MSW; для реального окружения нужен `VITE_API_BASE_URL` на backend.
- UI-kit собран минимально под задачу, без полноценной дизайн-системы.
